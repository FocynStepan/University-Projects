## 1. КЛОНУВАННЯ ТА ЕКСПОРТ ВІРТУАЛЬНОЇ МАШИНИ

### 1.1. Мета завдання
Створити незалежну копію існуючої робочої операційної системи та підготувати її до перенесення в інше середовище.

### 1.2. Клонування робочої ОС

Для безпечного масштабування та тестування мережі було створено клон базової віртуальної машини засобами гіпервізора Oracle VM VirtualBox.

**Параметри клонування:**
- **Тип клонування:** Повний клон (Full clone)
- **Генерація MAC-адрес:** Enable all network adapters
- **Результат:** Створено повністю ізольовану ВМ з унікальними апаратними ідентифікаторами

**Обґрунтування вибору:**
Повне клонування гарантує повну ізоляцію файлової системи та віртуального диска нової машини від оригіналу, що дозволяє незалежно експериментувати з налаштуваннями обох систем.

### 1.3. Експорт віртуальної ОС

Для перенесення налаштованої операційної системи на інший фізичний хост було виконано експорт віртуальної машини.

**Процес експорту:**
1. Меню **File → Export Appliance**
2. Вибір віртуальної машини для експорту
3. Вибір формату: **Open Virtualization Format (.ova)**
4. Збереження конфігурації ВМ (параметри процесора, пам'яті, образ диска)

**Переваги формату OVA:**
- Стандартизований формат для обміну віртуальними машинами
- Містить усі необхідні файли в одному архіві
- Підтримується більшістю гіпервізорів
- Зберігає всі налаштування та стан системи

## 2. ТИПИ ОРГАНІЗАЦІЇ МЕРЕЖЕВИХ З'ЄДНАНЬ

### 2.1. Мета завдання
Дослідити різні режими роботи віртуальних мережевих адаптерів, що пропонуються гіпервізором VirtualBox.

### 2.2. Основні типи мережевих підключень

#### 2.2.1. Трансляція мережевих адрес (NAT)

**Network Address Translation (NAT)**

**Принцип роботи:**
- Віртуальна машина виходить в Інтернет, використовуючи IP-адресу хостової ОС
- Гіпервізор виступає як маршрутизатор з функцією NAT
- Внутрішня IP-адреса ВМ залишається прихованою від зовнішньої мережі

**Переваги:**
-  Безпечне підключення до Інтернету
-  Не вимагає додаткових налаштувань
-  ВМ ізольована від зовнішньої мережі

**Недоліки:**
- ❌ ВМ не доступна ззовні
- ❌ Обмежена функціональність для серверних застосунків

**Використання:** Ідеально підходить для клієнтських ВМ, яким потрібен тільки вихід в Інтернет.

#### 2.2.2. Мережевий міст (Bridged Adapter)

**Bridged Networking**

**Принцип роботи:**
- Віртуальний мережевий інтерфейс підключається безпосередньо до фізичного мережевого адаптера хоста
- ВМ отримує власну унікальну IP-адресу в локальній мережі (через DHCP або статично)
- ВМ працює як окремий фізичний комп'ютер у мережі

**Переваги:**
-  ВМ повноцінний учасник локальної мережі
-  Доступна з інших пристроїв мережі
-  Повна функціональність мережевих служб

**Недоліки:**
- ❌ Менша ізоляція (потенційні ризики безпеки)
- ❌ Потребує вільних IP-адрес у мережі

**Використання:** Для серверів, які мають бути доступні в локальній мережі.

#### 2.2.3. Віртуальний адаптер хоста (Host-Only Adapter)

**Host-Only Networking**

**Принцип роботи:**
- Створюється закрита мережа виключно між хостовою ОС та віртуальними машинами
- Гіпервізор створює віртуальний мережевий адаптер на хості
- ВМ мають доступ тільки до хоста та одна до одної

**Конфігурація, використана в роботі:**
```
Адаптер: VirtualBox Host-Only Ethernet Adapter
IP хоста: 192.168.107.1/24
Мережа: 192.168.107.0/24
DHCP Server: Enabled (192.168.107.100-254)
```

**Переваги:**
-  Ізоляція від зовнішньої мережі
-  ВМ доступні з хоста
-  Безпечне тестування мережевих конфігурацій

**Недоліки:**
- ❌ Немає доступу до Інтернету (без додаткового адаптера)
- ❌ Обмежена сфера застосування

**Використання:** Для тестування мережевих взаємодій між ВМ, ізольованих лабораторних середовищ.

#### 2.2.4. Внутрішня мережа (Internal Network)

**Internal Network**

**Принцип роботи:**
- Найбільш ізольований режим
- Віртуальні машини спілкуються тільки між собою
- Хост та зовнішній світ не мають доступу до цієї мережі

**Переваги:**
-  Повна ізоляція
-  Безпека тестування шкідливого ПЗ
-  Моделювання закритих мереж

**Недоліки:**
- ❌ Неможливість взаємодії з хостом
- ❌ Обмежене практичне застосування

**Використання:** Для тестування мережевих атак, моделювання ізольованих інфраструктур.

## 3. РОЗГОРТАННЯ МЕРЕЖІ МІЖ РОБОЧОЮ ОС ТА КЛОНОМ

### 3.1. Мета завдання
Налаштувати мережеву взаємодію між двома віртуальними машинами для забезпечення обміну даними та перевірки зв'язку.

### 3.2. Вибір конфігурації мережі

Для виконання завдання обрано режим **Host-Only Adapter** з наступним обґрунтуванням:

**Причини вибору:**
1. Безпечне ізольоване середовище для тестування
2. Можливість взаємодії між ВМ
3. Контрольована мережева топологія
4. Відсутність конфліктів з основною мережею

**Початкові дані:**
```
ВМ 1: UbuntuServer2404
ВМ 2: Linux_Clone
Мережа: 192.168.107.0/24
Шлюз: 192.168.107.1 (хост)
```

### 3.3. Налаштування Host-Only мережі

#### 3.3.1. Створення віртуального адаптера

**Кроки налаштування:**

1. **VirtualBox Manager → File → Tools → Network Manager**

2. **Створення адаптера:**
   - Кнопка "Create"
   - Адаптер: VirtualBox Host-Only Ethernet Adapter
   - IPv4 Address: 192.168.107.1
   - IPv4 Network Mask: 255.255.255.0
   - Enable Adapter: 

3. **Налаштування DHCP Server:**
   - Enable Server: 
   - Server Address: 192.168.107.100
   - Lower Address: 192.168.107.101
   - Upper Address: 192.168.107.254

#### 3.3.2. Конфігурація віртуальних машин

**Для кожної ВМ:**
```
Settings → Network → Adapter 1
☑ Enable Network Adapter
Attached to: Host-Only Adapter
Name: VirtualBox Host-Only Ethernet Adapter
Promiscuous Mode: Allow All
```

### 3.4. Отримання IP-адрес та перевірка конфігурації

#### 3.4.1. Початкові проблеми

**Проблема 1: Конфлікт IP-адрес**

Після запуску обидві ВМ отримали однакову IP-адресу:
```
UbuntuServer2404: 192.168.107.3
Linux_Clone:      192.168.107.3  ❌ КОНФЛІКТ!
```

**Причина:** DHCP сервер видав однакові адреси через кешування або помилку.

**Рішення:**
```bash
# Перезапуск мережевого інтерфейсу
sudo systemctl restart systemd-networkd
sudo ip link set enp0s3 down
sudo ip link set enp0s3 up

# Отримання нової IP-адреси
sudo dhcpcd enp0s3
```

**Проблема 2: Відсутність dhclient**

В Ubuntu 24.04 за замовчуванням не встановлено стандартну утиліту `dhclient`.

**Рішення:** Використання `dhcpcd` (DHCP Client Daemon) замість `dhclient`.

#### 3.4.2. Фінальна конфігурація

**Після вирішення проблем:**

**ВМ 1 - UbuntuServer2404:**
```bash
stepan@stepan:~$ ip a
...

    inet 192.168.107.4/24 brd 192.168.107.255 scope global enp0s3
```

**ВМ 2 - Linux_Clone:**
```bash
stepan@stepan:~$ ip a
...
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> ...
    inet 192.168.107.5/24 brd 192.168.107.255 scope global enp0s3
```

**Перевірка зв'язку:**
```bash

ping -c 3 192.168.107.4
```

### 3.5. Обмін повідомленнями через netcat

#### 3.5.1. Теоретичні відомості

**Netcat (nc)** - універсальна утиліта командного рядка для читання та запису даних через мережеві з'єднання TCP та UDP.

**Основні режими роботи:**
- **Server mode:** `nc -l -p <port>` (прослуховування порту)
- **Client mode:** `nc <host> <port>` (підключення до сервера)

#### 3.5.2. Практична реалізація

**Крок 1: Запуск сервера на UbuntuServer2404**
```bash
stepan@ubuntu:~$ nc -l -p 1234
```
- Відкрито порт 1234 для прослуховування
- Термінал очікує підключення

**Крок 2: Підключення клієнта з Linux_Clone**
```bash
stepan@clone:~$ nc 192.168.107.4 1234
```
- Встановлено з'єднання з сервером
- Готовність до обміну даними

**Крок 3: Відправка повідомлень**

**З клієнта (Linux_Clone):**
```
Test
```

**На сервері (UbuntuServer2404) з'явилося:**
```
Test
```

**З сервера (UbuntuServer2404):**
```
test 2
```

**На клієнті (Linux_Clone) з'явилося:**
```
test 2
```

#### 3.5.3. Результати тестування

**Успішно перевірено:**
-  Встановлення TCP-з'єднання між ВМ
-  Двосторонній обмін даними
-  Коректна робота мережевого стеку
-  Відсутність блокування фаєрволом

**Важливе зауваження:**
За замовчуванням netcat закриває з'єднання після завершення вводу. Для постійного прослуховування використовується прапорець `-k`:
```bash
nc -l -p 1234 -k  # keep listening after client disconnects
```

### 3.6. Спроба налаштування SSHFS

#### 3.6.1. План реалізації

**SSHFS (SSH File System)** - файлова система, що монтується через SSH з'єднання, дозволяє отримати доступ до файлів віддаленої системи як до локальних.

**Заплановані кроки:**
1. Встановити SSH сервер на одній ВМ
2. Встановити SSHFS клієнт на іншій ВМ
3. Змонтувати віддалену папку
4. Перевірити доступ до файлів

#### 3.6.2. Виниклі проблеми

**Проблема: Відсутність доступу до Інтернету**

ВМ налаштовані в режимі Host-Only, що не забезпечує доступ до зовнішніх репозиторіїв Ubuntu.

**Спроба встановлення:**
```bash
stepan@stepan:~$ sudo apt install sshfs
Reading package lists... Done
W: Failed to fetch http://ua.archive.ubuntu.com/ubuntu/dists/noble/InRelease
Temporary failure resolving 'ua.archive.ubuntu.com'
E: Unable to fetch some archives, maybe run apt-get update?
```

**Аналіз проблеми:**
- ❌ DNS не працює (немає доступу до DNS серверів)
- ❌ Мережеві репозиторії недоступні
- ❌ Неможливо встановити нові пакунки

#### 3.6.3. Можливі рішення

**Рішення 1: Додати другий мережевий адаптер (NAT)**
```
Adapter 1: Host-Only Adapter (для зв'язку між ВМ)
Adapter 2: NAT (для доступу до Інтернету)
```

**Рішення 2: Використати Shared Folders VirtualBox**
- Не потребує Інтернету
- Простіше в налаштуванні
- Достатньо для обміну файлами

**Прийняте рішення:** Перейти до використання **Shared Folders** (див. Розділ 4).

## 4. ОБМІН ІНФОРМАЦІЄЮ МІЖ ОСНОВНОЮ ОС ТА ВІРТУАЛЬНИМИ ОС

### 4.1. Мета завдання
Налаштувати механізм обміну файлами між хостовою операційною системою Windows та віртуальними машинами Linux.

### 4.2. Shared Folders (Спільні папки)

#### 4.2.1. Теоретичні відомості

**Shared Folders** - функція VirtualBox, що дозволяє спільне використання папок між хостом та гостьовою ОС через спеціальну файлову систему `vboxsf`.

**Вимоги:**
- Встановлені **VirtualBox Guest Additions** на гостьовій ОС
- Налаштована спільна папка в конфігурації ВМ
- Користувач має бути доданий до групи `vboxsf`

#### 4.2.2. Налаштування Shared Folders

**Крок 1: Створення папки на хості (Windows)**
```
Шлях: C:\VM_Share
Дозволи: Full Control для поточного користувача
```

**Крок 2: Налаштування в VirtualBox**
```
Settings → Shared Folders
☑ Folder Path: C:\VM_Share
☑ Folder Name: Share
☑ Auto-mount
☑ Make Permanent
```

**Крок 3: Додавання користувача до групи vboxsf**
```bash
sudo usermod -aG vboxsf $USER
```

**Крок 4: Перезавантаження ВМ**
```bash
sudo reboot
```

#### 4.2.3. Перевірка та використання

**Автоматичне монтування:**
```bash
# Папка автоматично з'являється в:
/media/sf_Share/

# Перевірка прав доступу
ls -la /media/sf_Share/
```

**Ручне монтування (за потреби):**
```bash
sudo mount -t vboxsf Share /mnt/shared
```

### 4.3. Робота з файлами у терміналі

#### 4.3.1. Копіювання файлів з хоста до ВМ

**Вихідні дані:**
- Файл на хості: `C:\VM_Share\audio.mp3`
- Цільова папка: `~/Desktop/`

**Команда копіювання:**
```bash
cp /media/sf_Share/audio.mp3 ~/Desktop/
```

**Перевірка:**
```bash
ls -lh ~/Desktop/audio.mp3
# -rw-r--r-- 1 stepan stepan 3.5M Mar 13 20:00 audio.mp3
```

#### 4.3.2. Експорт файлів з ВМ на хост

**Створення тестового файлу:**
```bash
echo "Це тестовий документ з віртуальної машини" > ~/Desktop/document.txt
echo "Дата створення: $(date)" >> ~/Desktop/document.txt
echo "Користувач: $USER" >> ~/Desktop/document.txt
```

**Копіювання на хост:**
```bash
cp ~/Desktop/document.txt /media/sf_Share/
```

**Перевірка на хості (Windows):**
```cmd
dir C:\VM_Share\document.txt
type C:\VM_Share\document.txt

# Вміст:
Це тестовий документ з віртуальної машини
Дата створення: Thu Mar 13 20:05:00 EET 2026
Користувач: stepan
```

#### 4.3.3. Двосторонній обмін файлами

**Сценарій використання:**
1. Windows → ВМ: завантаження конфігураційних файлів, скриптів
2. ВМ → Windows: експорт логів, звітів, результатів роботи

**Приклад скрипта для автоматизації:**
```bash
#!/bin/bash
# backup_to_host.sh

SOURCE_DIR="/var/log"
BACKUP_FILE="system_logs_$(date +%Y%m%d).tar.gz"

# Створення архіву
tar -czf $BACKUP_FILE $SOURCE_DIR

# Копіювання на хост
cp $BACKUP_FILE /media/sf_Share/

echo "Backup completed: /media/sf_Share/$BACKUP_FILE"
```

## 6. ВИСНОВКИ

### 6.1. Досягнуті результати

У рамках виконання Work-case №3 було успішно виконано комплекс робіт з налаштування віртуалізованого середовища та мережевої взаємодії:

####  **Розділ 1: Клонування та експорт**
- Створено повний клон віртуальної машини з генерацією нових MAC-адрес
- Виконано експорт ВМ у формат OVA для перенесення
- Забезпечено повну ізоляцію файлових систем оригіналу та клону

####  **Розділ 2: Дослідження мережевих режимів**
- Практично досліджено 4 режими роботи мережевих адаптерів
- Визначено переваги та недоліки кожного режиму
- Обґрунтовано вибір Host-Only мережі для лабораторної роботи

####  **Розділ 3: Розгортання мережі**
- Налаштовано Host-Only мережу 192.168.107.0/24
- Вирішено проблему конфлікту IP-адрес (обидві ВМ отримали 192.168.107.3)
- Подолано складнощі з відсутністю dhclient в Ubuntu 24.04
- Успішно налаштовано зв'язок між ВМ (ping, netcat)
- Реалізовано обмін повідомленнями через netcat (порт 1234)

####  **Розділ 4: Обмін файлами**
- Налаштовано Shared Folders між Windows та Linux ВМ
- Відпрацьовано команди копіювання файлів в обох напрямках
- Забезпечено автоматичне монтування спільної папки

### 6.2. Вирішені проблеми

| Проблема | Причина | Рішення |
|----------|---------|---------|
| **Конфлікт IP** | DHCP видав однакові адреси | Перезапуск мережі через `dhcpcd` |
| **Немає dhclient** | Ubuntu 24.04 не має за замовчуванням | Використання `dhcpcd` |
| **Не працює SSHFS** | Немає доступу до Інтернету | Перехід на Shared Folders |
| **Немає доступу до репозиторіїв** | Host-Only не дає Інтернет | Налаштування Shared Folders замість apt |
