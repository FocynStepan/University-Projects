## ВСТУП

Сучасні операційні системи сімейства Linux посідають провідні позиції у серверній інфраструктурі, хмарних обчисленнях, вбудованих пристроях та десктоп-середовищах. Однією з фундаментальних підсистем, що визначає надійність, продуктивність та безпеку ОС, є файлова система (ФС). На відміну від пропрієтарних (закритих комерційних) рішень, Linux пропонує модульну архітектуру, підтримку десятків ФС різного призначення та єдину абстракцію взаємодії з даними.

**Мета реферату:** проаналізувати загальний підхід Linux до організації файлових систем, порівняти ключові рішення та детально розглянути їх реалізацію в Ubuntu 24.04 LTS (Long Term Support – версія з довготривалою підтримкою) із графічним середовищем GNOME (GNU Network Object Model Environment – вільне графічне робоче середовище).

**Завдання:**

- Проаналізувати вибір та налаштування ФС у Ubuntu 24.04 LTS.
- Дослідити інтеграцію файлових систем із GNOME та сучасні механізми управління даними.

**Об'єкт дослідження:** файлові системи в ОС Linux.

## 1. ЗАГАЛЬНИЙ ПІДХІД ДО ФАЙЛОВИХ СИСТЕМ У LINUX

Архітектура Linux ґрунтується на кількох принципових ідеях, що відрізняють її від інших ОС:

- **Філософія «Everything is a file» (Все є файл):** У Linux апаратні пристрої, мережеві сокети, процеси, системні параметри та інтерфейси представлені як файли (через файлові дескриптори) в єдиній ієрархії. Це спрощує адміністрування та уніфікує API (Application Programming Interface – програмний інтерфейс застосунків) взаємодії.
- **VFS (Virtual File System – віртуальна файлова система) та її логічні об'єкти:** VFS – це шар абстракції між ядром ОС та конкретними ФС на диску. Він надає уніфікований інтерфейс (команди `open`, `read`, `write`, `mount`), дозволяючи ядру працювати з різноманітними ФС без зміни програм користувача. Архітектура VFS спирається на чотири базові об'єкти:
  - `Superblock` (Суперблок): містить глобальні дані про змонтовану ФС (загальний розмір, стан, тип).
  - `Inode` (Index Node – індексний вузол): зберігає метадані файлу (права доступу, власник, часові мітки, розмір) та вказівники на фізичні блоки даних на диску.
  - `Dentry` (Directory Entry – запис каталогу): пов'язує символьне ім'я файлу з його `inode`, забезпечуючи ієрархію та прискорюючи пошук через кеш пам'яті.
  - `File` (Файл): структура, що представляє відкритий процесом файл (містить поточне зміщення для читання чи запису).
- **FHS (Filesystem Hierarchy Standard – стандарт ієрархії файлових систем) та псевдофайлові системи:** На відміну від Windows з літерами дисків (`C:\`, `D:\`), Linux використовує єдине кореневе дерево `/`. Кожен пристрій «монтується» у певну директорію (наприклад, `/home`, `/boot`). Окремо виділяють псевдофайлові системи, які існують лише в RAM (Random Access Memory – оперативна пам'ять): `/dev` (апаратні пристрої), `/proc` (дані про процеси) та `/sys` (інтерфейс взаємодії з драйверами).
- **FUSE (Filesystem in Userspace – файлова система у просторі користувача):** Дозволяє реалізовувати ФС без зміни ядра системи. Це підвищує стабільність (помилка у FUSE-ФС не викликає критичного збою ядра – *kernel panic*). Приклади: `sshfs`, `rclone`, `encfs`.
- **POSIX-сумісність, атрибути та фізична організація:** Linux дотримується стандартів POSIX (Portable Operating System Interface – переносний інтерфейс операційних систем): права `rwx` (читання/запис/виконання), підтримка ACL (Access Control List – список контролю доступу) та extended attributes (розширені атрибути). На фізичному рівні ФС ведуть облік вільних блоків за допомогою bitmaps (бітових карт) та використовують journaling (журналювання) для збереження цілісності після збоїв живлення.

## 2. ОСНОВНІ ФАЙЛОВІ СИСТЕМИ LINUX: ПОРІВНЯННЯ ТА ЗАСТОСУВАННЯ

| ФС | Тип | Ключові особливості | Сценарії використання |
|---|---|---|---|
| `ext4` (Fourth Extended Filesystem – четверта розширена ФС) | Журнальована | Стабільність, використання extents (екстентів – неперервних областей блоків) для уникнення фрагментації, файли до 16 ТБ. | Десктопні ПК, сервери загального призначення. |
| `Btrfs` (B-Tree File System – ФС на основі B-дерев) | CoW (Copy-on-Write – копіювання під час запису) | Снапшоти (миттєві знімки стану), інтегроване стиснення, підтримка RAID (Redundant Array of Independent Disks – надлишковий масив незалежних дисків). | Розробка, тестування, резервне копіювання. |
| `XFS` (eXtents File System – ФС на основі екстентів) | Журнальована | Висока пропускна здатність, швидка робота з великими файлами, паралельний доступ до даних. | Відеомонтаж, Big Data, корпоративні сховища. |
| `ZFS` (Zettabyte File System – зетабайтна файлова система) | CoW + RAID | ARC-кеш (Adaptive Replacement Cache – адаптивний кеш заміни), дедуплікація, самовідновлення, ліцензія CDDL (Common Development and Distribution License). | Сервери, NAS (Network Attached Storage – мережеві сховища даних). |
| `tmpfs` (Temporary File System) | Віртуальна | Розміщується в оперативній пам'яті (RAM), має динамічний розмір, дуже швидкий доступ. | Тимчасові файли (`/tmp`, `/run`), кешування. |
| `squashfs` | Стиснута | Працює в режимі Read-only (тільки для читання), має надвисоке стиснення, монтується як loop-пристрій (віртуальний диск із файлу). | Дистрибутиви LiveCD (системи на флешках), контейнери, Snap-пакети. |

**Висновок розділу:** Linux не нав'язує єдину ФС. Вибір залежить від задач: `ext4` – універсальний стандарт, `Btrfs`/`ZFS` – для просунутого управління даними, `XFS` – для високого навантаження.

## 3. ФАЙЛОВІ СИСТЕМИ В UBUNTU 24.04 LTS: ОСОБЛИВОСТІ ТА НАЛАШТУВАННЯ

Ubuntu 24.04 LTS «Noble Numbat» продовжує стратегію балансу між стабільністю та інноваціями.

### 3.1. Вибір ФС за замовчуванням

- **Десктоп (GNOME):** `ext4` для кореневого розділу (`/`). Обґрунтування: перевірена часом стабільність, мінімальні вимоги до обслуговування, повна підтримка інструментів.
- **Сервер:** інсталятор пропонує `ZFS` як опцію для root pool (кореневого пулу/сховища), а також підтримує `Btrfs` та `XFS` через ручне розбиття дисків.
- **Шифрування:** за замовчуванням підтримується стандарт `LUKS2` (Linux Unified Key Setup – уніфіковане налаштування ключів Linux) поверх `LVM2` (Logical Volume Manager – менеджер логічних томів) за допомогою модуля ядра `dm-crypt`. Ключі зберігаються в `initramfs` (Initial RAM file system – початкова віртуальна ФС), розблокування відбувається на етапі завантаження ПК.

### 3.2. Типова схема розбиття

/dev/sda1  EFI System Partition (FAT32, /boot/efi) – 512 MB
/dev/sda2  Linux filesystem (ext4, /) – 40–100 GB
/dev/sda3  Linux swap (файл або розділ підкачки) – дорівнює RAM × 1 або 2
/dev/sda4  /home (окремо або в межах кореня /)


> **Примітка:** Для системного розділу EFI (Extensible Firmware Interface – розширюваний інтерфейс мікропрограм) обов'язковим є форматування у `FAT32` (File Allocation Table – 32-бітна таблиця розміщення файлів). Для зовнішніх USB-накопичувачів великого об'єму Ubuntu нативно підтримує `exFAT` (Extensible FAT – розширена таблиця розміщення файлів). Простір `swap` (віртуальна пам'ять на диску) найчастіше реалізується як файл (`/swapfile`), що спрощує динамічне управління об'ємом.

### 3.3. Інструменти управління

| Утиліта | Призначення |
|---|---|
| `gnome-disks` | Графічне монтування, форматування, діагностика SMART (Self-Monitoring, Analysis, and Reporting Technology – технологія самоконтролю дисків), робота з LUKS. |
| `gparted` | Просунуте візуальне розбиття диска, зміна розмірів розділів, перевірка ФС. |
| `lsblk`, `df` | Консольні утиліти для отримання інформації про блокові пристрої та вільне місце. |
| `btrfs-progs` | Набір утиліт для роботи зі снапшотами, субтомами та балансування у Btrfs. |
| `zfsutils-linux` | Інструменти для управління пулами (pools), датасетами та стисненням у ZFS. |

### 3.4. Тенденції в Ubuntu 24.04

- **Екосистема Snap:** Масове використання Snap-пакетів. Кожен такий застосунок використовує образ `squashfs` і монтується системою як окремий `loop`-пристрій, що забезпечує жорстку ізоляцію – *sandbox* (пісочницю) на рівні файлової системи.
- **Поступове впровадження Btrfs** для створення бекапів десктопа через `Timeshift` або `snapper`.
- **Офіційна підтримка ZFS** у серверній редакції.
- **Автоматичне монтування дисків** через `systemd.mount` та файл конфігурації `/etc/fstab`.

## 4. ІНТЕГРАЦІЯ З GNOME: УПРАВЛІННЯ ФАЙЛАМИ ТА ВІРТУАЛЬНІ ФС

GNOME 46 (графічна оболонка за замовчуванням в Ubuntu 24.04) забезпечує сучасний та зручний доступ до даних, приховуючи від користувача складність консольних команд. Інтеграція файлових систем у GNOME реалізована через багатошарову архітектуру, що поєднує локальні ФС, мережеві протоколи, хмарні сховища та ізольовані середовища застосунків.

### 4.1. GNOME Files (Nautilus)

- **Графічний інтерфейс та продуктивність:** Nautilus у GNOME 46 отримав оптимізації рендерингу, покращене кешування мініатюр, підтримку Wayland-сесій без додаткових обхідних шляхів та розширену роботу з тегами (через інтеграцію з `tracker3`). Додано швидкий фільтр у реальному часі, групування за типами та покращену навігацію шляхом історії переходів.
- **Інтеграція з підсистемами ОС:** Автоматичне монтування знімних носіїв реалізовано через `udisks2` та `systemd-udevd`. Запит прав адміністратора (наприклад, для форматування або доступу до системних розділів) обробляється `polkit` через графічний діалог, що запобігає необхідності використання терміналу.
- **Мережеві протоколи:** Нативна підтримка `SMB` (Server Message Block), `FTP`, `SFTP`, `WebDAV` та `NFS`. Підключення відбувається через URI-схеми (`smb://`, `ftp://`), а обробка сесій делегується GVfs-бекендам.
- **Управління кошиком:** На відміну від класичного видалення, Nautilus переміщує файли у `~/.local/share/Trash`, зберігаючи метадані про початковий шлях та час видалення у файлах `.trashinfo`. Це дозволяє безпечне відновлення без втрати контексту.

### 4.2. GVfs (GNOME Virtual File System) та архітектура віртуального доступу

- **Заміна FUSE на D-Bus:** Сучасні версії GVfs поступово відходять від обов'язкового використання FUSE на користь комунікації через D-Bus та Unix-сокетів. Це підвищує безпеку (ізоляція процесів) та продуктивність, зменшуючи накладні витрати на контекстні перемикання між простором користувача та ядром.
- **Демонна архітектура (`gvfsd`):** GVfs працює як набір фонових демонів (`gvfsd`, `gvfsd-fuse`, `gvfsd-ftp`, `gvfsd-mtp` тощо). Кожен бекенд відповідає за конкретний протокол або тип сховища. Центральний демон `gvfsd` керує сесіями, моніторингом змін та маршрутизацією запитів.
- **Бібліотека GIO:** Усі графічні та консольні застосунки GNOME використовують `libgio` (частина GLib) для взаємодії з файлами. GIO автоматично визначає, чи працює файл локально чи віртуально, і прозоро делегує операції відповідному GVfs-бекенду. Це забезпечує єдиний API для `open()`, `read()`, `write()`, `copy()` незалежно від фізичного розташування даних.
- **Точки монтування:** Віртуальні ФС монтується у `/run/user/$(id -u)/gvfs/`. Для додатків, що не підтримують GIO, GVfs надає FUSE-сумісний шар (`gvfsd-fuse`), який створює симлінки у цій директорії, забезпечуючи зворотну сумісність із legacy-програмами.

### 4.3. xdg-desktop-portal та модель безпеки для ізольованих застосунків

- **Концепція порталів (Portals):** У сучасному GNOME прямий доступ ізольованих застосунків (Flatpak, Snap, AppImage) до файлової системи обмежено. Замість цього використовується `xdg-desktop-portal` – системний посередник, який надає безпечний API через D-Bus.
- **File Chooser Portal:** Дозволяє застосункам викликати стандартне діалогове вікно вибору файлів. Користувач явно підтверджує доступ, після чого портал надає тимчасовий файловий дескриптор або копію файлу у безпечну директорію застосунку.
- **Document Portal:** Реалізує принцип мінімального доступу. Якщо застосунок відкриває документ, йому надається доступ лише до цього конкретного файлу (через `bind-mount` у окремому `mount namespace`), а не до всієї директорії. Це запобігає масовому зчитуванню даних у фоновому режимі.
- **Інтеграція з sandbox:** Flatpak використовує `bubblewrap` для створення ізольованих просторів імен (PID, mount, network, user). Snap застосовує `apparmor`-профілі та `seccomp`-фільтри. Обидва підходи покладаються на портали для легітимного та аудованого

### 4.5. Індексація та семантичний пошук (Tracker 3)

- **Архітектура Tracker 3:** Замість старого Tracker 2, у Ubuntu 24.04 використовується Tracker 3, переписаний з використанням SPARQL-бази даних (`tracker-store`). Він індексує метадані файлів (теги, автор, дата створення, GPS, EXIF, PDF-вміст, аудіо-теги) у `~/.cache/tracker3/`.
- **Мінери (Miners):** `tracker-miner-fs-3` сканує локальні директорії, `tracker-miner-rss-3` обробляє стрічки, а інтеграція з GVfs дозволяє індексувати мережеві та хмарні файли (з обмеженнями через портали безпеки).
- **Продуктивність та приватність:** Tracker 3 працює з нижчим пріоритетом (`ionice`, `nice`), не індексує приховані файли за замовчуванням, підтримує виключення через `~/.config/tracker3/miner-fs.cfg`. Пошук у Nautilus використовує SPARQL-запити, що забезпечує миттєвий відгук навіть на сховищах об'ємом у терабайти.
- **Керування:** Індекс можна очистити командою `tracker reset --hard`. Для систем з обмеженими ресурсами індексацію можна призупинити через `systemctl --user mask tracker-miner-fs-3.service`, зберігаючи функціональність пошуку за іменами файлів.

## ВИСНОВКИ

1. Linux має гнучку архітектуру файлових систем VFS, яка дозволяє працювати з багатьма типами ФС.
2. В Ubuntu 24.04 LTS `ext4` залишається хорошим вибором для повсякденної роботи, але `Btrfs` і `ZFS` дають більше можливостей для просунутих користувачів.
3. Snap-пакети використовують ФС `squashfs`, що забезпечує їх ізоляцію та безпеку.
4. GNOME надає зручний інтерфейс для роботи з файлами завдяки GVfs і сучасним технологіям доступу.

**Порада:** Для базового користувача – `ext4` + шифрування диска; для розробників – `Btrfs`; для серверних даних – `ZFS`.
